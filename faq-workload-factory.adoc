當您設定和管理 NetApp Workload Factory 時，您可能會對帳戶、認證資料、連結和自動化工具的概念、術語、行為和限制有常見的疑問。



[[overview-and-costs]]
== 概述和成本

.Workload Factory 是什麼？它的價格是多少？
Workload Factory 是一個生命週期管理平台，用於最佳化執行在 FSx for ONTAP 檔案系統上的工作負載，例如資料庫、VMware 遷移和 EDA 專案。Workload Factory 本身可以免費使用。您需要為部署的服務向 AWS 付費，例如 FSx for ONTAP 檔案系統、VMware Cloud on AWS 基礎架構和其他 AWS 服務。

link:workload-factory-overview.html["了解 Workload Factory"]。

.Workload Factory 可在哪些 AWS 區域使用？
Workload Factory 可在所有支援 FSx for ONTAP 的商業區域運行，但在中國區域、Secret Cloud 或 Top Secret Cloud 中不可用。

https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/["查看支援的 AWS 區域。"^]



[[accounts-and-sign-in]]
== 帳戶和登入

.Workload Factory 控制台和 NetApp Console 有什麼不同？
兩者都是網路型的控制台，可讓您存取 Workload Factory。NetApp Console 提供混合體驗，您可以在一個位置管理 FSx for ONTAP 檔案系統和工作負載以及其他資料服務。Workload Factory 控制台提供專用體驗，專注於在 FSx for ONTAP 上執行的工作負載。

link:console-experiences.html["決定使用哪個主控台"]。

.我該如何註冊？建立我的第一個帳戶時會發生什麼事？
使用您的 NetApp 支援網站（NSS）認證資料註冊或建立 NetApp 雲端登入。對於雲端登入，您必須先驗證您的電子郵件地址才能登入。首次登入時，您會建立一個帳戶，用於組織您的資源、工作負載和認證資料，並且您將成為帳戶管理員，可存取所有 Workload Factory 功能。如果您已在使用 NetApp Console，則您已屬於一個帳戶，因為 Workload Factory 使用 NetApp 帳戶。

link:sign-up-and-log-in.html["註冊並登入"]。

.我應該將我的帳戶設定為 AWS GovCloud（美國）帳戶嗎？以後可以更改嗎？
如果您需要僅使用 GovCloud (US) 端點和區域的帳戶，且認證資料和機密保留在 GovCloud 中，請選擇 GovCloud (US) 選項。此選擇為永久性設定。GovCloud 帳戶必須手動新增認證資料並建立連結。

.如何邀請其他使用者加入我的 Workload Factory 帳戶？
您只能從 NetApp Console 管理您的帳戶。帳戶管理員在該處新增成員，受邀使用者將收到一封包含參加說明的電子郵件。

link:sign-up-and-log-in.html["邀請其他使用者加入您的帳戶"]。



[[credentials-and-permissions]]
== 憑證和權限

.我是否需要新增 AWS 認證資料才能使用 Workload Factory？
新增認證資料是開始使用的選用步驟，因此您無需存取 AWS 帳戶即可使用 Workload Factory。但是，若要建立與管理 FSx for ONTAP 檔案系統，以及部署與管理資料庫等工作負載，Workload Factory 需要認證資料。

* link:quick-start.html["開始使用 Workload Factory"]。
* link:add-credentials.html["新增憑證"]。


.Workload Factory 認證資料是如何運作的？
認證資料使用 AWS 角色承擔流程。每組認證資料包含一個或多個 IAM 原則（取決於您選擇的工作負載功能和權限等級）以及 Workload Factory 承擔的 IAM 角色。您可以隨時新增更多功能。

link:add-credentials.html["新增憑證"]。

.我應該手動新增認證資料還是使用 CloudFormation？
使用手冊方法，您可以在 AWS 管理主控台中建立 IAM 原則和 IAM 角色，從 Codebox 複製原則 JSON。使用自動方法，您選擇功能後，CloudFormation 堆疊會為您建立 IAM 原則和 IAM 角色。GovCloud（美國）認證資料必須手動新增，因為該處不支援 CloudFormation。

link:add-credentials.html["新增憑證"]。

.我可以選擇哪些權限級別，以及如何決定要授予哪些權限？
權限原則依工作負載進行分組。對於儲存設備，選項包括 *檢視、規劃和分析*、*操作和修復*，以及 *檔案系統建立和刪除*。資料庫工作負載提供 *檢視、規劃和分析*、*操作和修復*，以及 *資料庫主機建立*。這些原則可讓您根據 IT 原則遞增指派信任。請僅選擇您目前規劃使用的功能。

link:permissions-reference.html["權限參考"]。

.自動權限檢查有什麼作用？我應該保持啟用嗎？
選取 *Enable automatic permissions check* 會將 `iam:SimulatePrincipalPolicy`新增至您的權限原則，以便 Workload Factory 在完成作業之前確認您具有必要的 AWS 權限。您可以在新增認證資料後將其移除，但建議保留。它可以防止在作業部分成功的情況下建立資源，並避免您手冊清理資源。

link:add-credentials.html["新增認證資料時啟用自動權限檢查"]。

.我可以刪除不再需要的認證資料嗎？
只有當認證資料未與 FSx for ONTAP 檔案系統關聯時，才能將其刪除。在 Workload Factory 主控台中使用「移除」，或在 NetApp Console 中使用「刪除」。

link:manage-credentials.html["移除認證資料"]。



[[links]]
== 連結

.什麼是連結？我需要連結嗎？
Link 可在 Workload Factory 帳戶與一個或多個 FSx for ONTAP 檔案系統之間建立信任關係與連線。Link 使用 AWS Lambda，因此您可以透過 ONTAP REST API 呼叫來監控和管理 Amazon FSx for ONTAP API 未提供的功能。您不需要 Link 即可開始使用，但需要一個 Link 才能解除鎖定 Workload Factory 的所有功能。

link:links-overview.html["深入瞭解連結"]。

.哪些功能需要連結？
需要連結的功能包括：

* FSx for ONTAP 的良好架構狀態
* ONTAP EMS 事件監控
* 基於人工智慧的自主勒索軟體防護（ARP/AI）
* Volume 和儲存設備 VM 複寫
* SMB/CIFS 共享和 NFS 匯出原則
* iSCSI Volume 管理
* Snapshot 快照技術原則
* Volume 自動擴充與 inode 管理
* 複製建立
* 額外的 ONTAP 計量與 LIF 詳細資料


如果您嘗試執行需要連結但未關聯任何連結的操作，Workload Factory 會通知您。請參閱 link:links-overview.html["深入瞭解連結"]。

.連結會增加費用嗎？
是的。每筆 Lambda 交易都會產生 AWS 費用。因為 Lambda 充當 Proxy，所以當它向檔案系統上的 ONTAP REST API 發送請求時，以及當它將回應傳回 Workload Factory 時，都會向您收費。

link:links-overview.html["深入瞭解連結"]。

.一個檔案系統可以關聯多個連結嗎？
一個連結可以關聯多個 FSx for ONTAP 檔案系統。每個檔案系統在同一個 NetApp 帳戶中只能關聯一個連結。如果您有多個 NetApp 帳戶，則一個檔案系統可以關聯不同帳戶下的其他連結。請參閱 link:links-overview.html["深入瞭解連結"]。

.我應該自動建立連結還是手動建立連結？
自動建立會透過 Workload Factory 註冊連結，但它會使用權杖進行 Workload Factory 自動化，且其 CloudFormation 程式碼最多只能使用六小時。手動建立會使用 Codebox 中的 CloudFormation 或 Terraform，且程式碼會保留。當安全性與 DevOps 開發維運等團隊必須先授予權限時，這非常有用。GovCloud 帳戶必須手動建立連結。

link:create-link.html["建立連結"]。

.在建立連結之前，我需要準備什麼？
您需要在檔案系統的安全性群組中開啟所需的連接埠，讓 Link 能夠連線至 `\https://api.workloads.netapp.com`，並具備足夠的 AWS 權限來建立 CloudFormation 堆疊。

link:create-link.html["了解建立 Link 的完整先決條件清單"]。

.我可以變更連結的身分驗證方式，或是在建立連結後對其進行編輯嗎？
不。Link 僅支援一種身分驗證方法，即 Workload Factory 認證資料或 AWS Secrets Manager，之後無法變更。

您無法在介面中編輯連結。若要變更連結，請建立新的連結並將其與檔案系統建立關聯。不建議在 AWS 中變更 Lambda 網路組態，因為這可能會導致連線問題。

link:manage-links.html["管理連結"]。

.移除連結會發生什麼事？
使用該連結的檔案系統和其他資源將無法再使用依賴該連結的功能。該連結僅從 Workload Factory 中刪除，不會從 AWS 中刪除，因此您也必須從 AWS 帳戶中刪除 Lambda 函數。

link:manage-links.html["移除連結"]。



[[codebox]]
== Codebox

.Codebox 是什麼？它能產生哪些程式碼格式？
Codebox 是一個基礎架構即程式碼輔助工具，可產生程式碼以執行 Workload Factory 支援的任何操作。它支援 Workload Factory REST API、AWS CLI、AWS CloudFormation 和 Terraform。Codebox Viewer 會顯示從您的精靈輸入內容產生的程式碼，而自動化目錄會將儲存的作業儲存為可重複使用的範本。

link:codebox-automation.html["深入瞭解 CodeBox"]。

.我可以在 Codebox 中編輯程式碼嗎？產生的程式碼會過期嗎？
Codebox Viewer 為唯讀模式。您只能複製程式碼、將其儲存至 Automation Catalog，或下載某些格式的程式碼。您可以編輯下載的程式碼，使其適用於其他 AWS 帳戶。CloudFormation YAML 程式碼基於安全性考量，會在七天後過期。

link:use-codebox.html["使用 Codebox"]。



[[cloudshell]]
== CloudShell

.我可以在 CloudShell 中做什麼，它的限制是什麼？
CloudShell 使用您提供的 AWS 和 ONTAP 認證資料，透過 Workload Factory 後端 Proxy，在以瀏覽器為基礎的 shell 中執行 AWS CLI 和 ONTAP CLI 命令。它至少需要一個 AWS 認證資料。不支援管線 `|`、背景 `&`和重新導向 `>`等 shell 運算子，包含這些運算子的命令將會失敗。只有當選取的認證資料在所選區域中擁有權限時，AWS 命令才能成功。

link:use-cloudshell.html["使用 CloudShell"]。



[[notifications]]
== 通知

.Workload Factory 可以將通知傳送到哪裡，以及由誰控制這些通知？
Workload Factory 可以將通知以 NetApp Console 警示、傳送至與帳戶相關聯的電子郵件地址，或傳送至 Amazon SNS 主題的形式發送。當您部署 Console 代理程式或 Link 時，就會顯示 Console 警示。當您在 NetApp Console 中設定通知時，它會接管傳遞作業，而 Workload Factory 主控台通知選項將變成唯讀。

link:configure-notifications.html["設定通知"]。

.在使用 Amazon SNS 進行關鍵警報之前，我應該了解哪些內容？
Workload Factory 僅支援標準 SNS 主題類型，無法保證通知會依接收順序送達訂閱者。請謹慎考慮此特性，尤其是在關鍵或緊急通知時。預設情況下，訂閱者會收到主題上的所有通知，因此請使用 SNS 過濾原則（按資源類型、工作負載、優先順序或通知類型）來僅接收所需內容。

link:configure-notifications.html["設定通知"]。



[[service-accounts]]
== 服務帳戶

.我應該何時使用服務帳戶？關於它的密鑰，我應該了解哪些資訊？
使用服務帳戶進行僅限 API 的自動化，這樣指令碼就不會依賴個人的使用者帳戶。用戶端機密僅會顯示一次，且 Workload Factory 不會將其儲存，因此請在建立服務帳戶時建立複本或下載。從用戶端 ID 和機密產生的存取權杖時效很短，僅能持續數小時。在 Workload Factory 主控台中，您只能建立或刪除服務帳戶。若要取得新的機密，請刪除服務帳戶並建立新的帳戶。

link:manage-service-accounts.html["管理服務帳戶"]。



[[well-architected-analysis]]
== 精心設計的分析

.架構良好的分析如何運作，是否需要 Link？
Workload Factory 每天掃描 FSx for ONTAP 檔案系統。它會將組態評為最佳化的或未最佳化的，提供建議，並能自動修復某些問題，而其他問題則需要手冊步驟。您可以忽略不適用於您環境的檢查，或使用純文字語言建立自訂規則。若要對檔案系統進行全面分析，您需要建立連結並將其與檔案系統關聯。

link:well-architected-workloads.html["深入瞭解架構良好的分析"]。



[[tracker]]
== 追蹤器

.Tracker 是什麼？它會保留多久的作業歷史記錄？對於失敗的作業，我該如何處理？
Tracker 是 Workload Factory 中的監控工具，會在使用者介面中保留 30 天的事件。您可以按時間範圍、工作負載、狀態和使用者進行篩選，並將作業表下載為 CSV 檔案。對於失敗的操作，您可以重試，也可以編輯其參數後再重試。失敗操作的重試次數有限制。

link:monitor-operations.html["使用 Tracker 監控作業"]。



[[ai-features]]
== 人工智慧功能

.如何控制 AI 功能，如果將其關閉會發生什麼事？
在 AI 設定頁面，管理員可以選擇 NetApp 代管的 Bedrock（建議）或關閉所有 AI 功能。NetApp 代管的 Bedrock 不會使用您的資料來訓練模型，也無需額外的 AWS 設定。關閉 AI 功能會使「問我」、AI 代理程式、自訂儀表板、規則建構者、分析器以及 CloudShell 中的 AI 錯誤回應無法使用。AI 功能在公共 AWS 區域中使用 AWS Bedrock，這對 GovCloud 帳戶可能會有影響。

link:manage-genai-features.html["管理 AI 功能"]。

.人工智慧的使用是否有限制？
是的。使用 NetApp 代管的 Bedrock，每個帳戶的每項 AI 功能都有每月消費限額。當達到限額時，Workload Factory 會關閉 AI 功能，將介面的相關部分變灰，並顯示工具提示。若要取得更多額度，請聯絡您的 NetApp 代表。

.AI 代理程式可以更改我的 AWS 或 ONTAP 資源嗎？
預設情況下，代理程式以唯讀模式執行，無法變更資源。在選用的讀寫模式下，代理程式會摘要說明每個行動，並在您核准後，使用您選取的認證資料來執行。代理程式只能存取您目前範圍內的資源以及在代理程式設定中選擇的認證資料，且選擇認證資料不會授予額外的 AWS 權限。

* link:learn-agent.html["了解人工智慧代理程式"]。
* link:manage-agent-settings.html["管理代理程式設定"]。




[[custom-dashboards]]
== 自訂儀錶板

.誰可以查看、編輯或刪除自訂儀表板？
新的儀表板僅建立者可見。共用會將儀表板公開給 Workload Factory 帳戶中的所有人，但您無法共用到帳戶外部。只有建立者才能編輯儀表板，但帳戶中的所有使用者都可以刪除儀表板。刪除是永久性的，並且會為所有人移除該儀表板，因此請與您的團隊協調。

* link:learn-custom-dashboards.html["了解自訂儀表板"]。
* link:manage-custom-dashboards.html["管理自訂儀表板"]。


.建立和使用自訂儀表板需要哪些準備工作？
您的帳戶管理員應啟用 AI 功能。您需要擁有對要監控的服務具備讀取存取權限的 AWS 憑證。您需要一個 Link 才能連接至 FSx for ONTAP 檔案系統。儀表板為唯讀，無法變更您的儲存設備或工作負載設定。

link:learn-custom-dashboards.html["了解自訂儀表板"]。
